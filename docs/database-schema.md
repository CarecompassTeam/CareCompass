# Database Schema

## Status

The database technology and schema have not been finalized.

## What to Document

For each entity or table, document:

- Name and purpose.
- Fields and data types.
- Primary key.
- Foreign keys and relationships.
- Required and optional fields.
- Constraints and indexes.
- Sensitive data and access restrictions.

## Entity Relationships

Add an entity-relationship diagram here after the team agrees on the data model.

## Design Guidelines

- Store only data needed by the application.
- Apply appropriate access controls.
- Validate data before storing it.
- Never include real user records, passwords, or secrets in example data.
- Document schema changes so frontend and backend developers can coordinate.
